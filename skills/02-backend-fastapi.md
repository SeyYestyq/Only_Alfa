# Backend: FastAPI + PostgreSQL

## Структура (слои, зависимости сверху вниз)

```
app/
  api/            # роуты и Pydantic-схемы (вход/выход), никакой бизнес-логики
  services/       # сценарии: создать заявку, подтянуть мультибанк, действие инспектора
  domain/         # чистый Python: scoring/, decision/, state_machine/, validators/
  repositories/   # SQLAlchemy: единственное место с SQL
  infra/          # адаптеры симуляторов реестров, гео-кэш, парсер PDF
  core/           # конфиг, константы, исключения, логирование
```

## Правила

1. **Роуты тонкие.** Роут: принял запрос → вызвал сервис → вернул схему. Валидация бизнес-правил — в домене, не в роуте и не в Pydantic.
2. **Схемы ≠ модели.** Pydantic-схемы API, ORM-модели и доменные сущности — три разных представления; маппинг явный, в одном месте на сущность.
3. **State Machine — только домен.** Переход статуса: сервис → `state_machine.transition(app, target, actor)` → валидация перехода → запись в `application_events` в той же транзакции. Прямые присваивания `application.status = ...` вне машины запрещены.
4. **Транзакции на границе сервиса.** Один сценарий = одна транзакция. Частично записанных заявок быть не может.
5. **Сидинг идемпотентный.** `INSERT ... ON CONFLICT DO NOTHING` / проверка существования. Повторный `docker compose up` не плодит дубли и не падает.
6. **Симуляторы реестров — за интерфейсом** `RegistryProvider` с таймаутом 2 сек и детерминированным фолбэком `seed = hash(INN)`. Один ИНН — всегда один результат, включая офлайн-режим.
7. **Ошибки.** Доменные исключения → HTTP в одном обработчике: `InvalidTransition` → 409, нарушение роли → 403, валидация → 422. Тексты ошибок — на языке бизнеса, без внутренних деталей и трейсов наружу.
8. **Конфиг** — только через переменные окружения и `core/config.py`; никаких захардкоженных URL/порогов в коде.
9. **Миграции и схема** меняются вместе с кодом в одном PR; `openapi.yaml` перегенерируется при любом изменении контракта.
10. **Логирование:** каждый переход State Machine и каждое решение Decision Engine — структурированная запись (application_id, actor_role, rule_code). Без персональных данных в логах сверх нужного для аудита.
