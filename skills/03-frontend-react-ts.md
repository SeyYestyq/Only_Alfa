# Frontend: React + TypeScript

## Структура

```
src/
  api/          # сгенерированные/ручные типы из OpenAPI + клиент запросов
  pages/        # экраны: ClientDashboard, ApplicationFlow, InspectorDesk
  components/   # переиспользуемые компоненты по фичам: dna/, radar/, search/, offers/
  hooks/        # доступ к данным и состоянию
  domain-ui/    # чистое форматирование: деньги, даты, подписи статусов
```

## Правила

1. **Фронт не считает бизнес.** Баллы, лимиты, офферы, статусы и переходы приходят с бэкенда. На фронте — только отображение и форматирование. Запрещены «временные» локальные расчёты скоринга и хардкод сценариев.
2. **Типы — из OpenAPI.** Типы запросов/ответов не пишутся руками «по памяти» — генерируются из `openapi.yaml` или сверяются с ним при каждом изменении контракта.
3. **Компонент = одна ответственность (S из SOLID).** Компонент > 200 строк или с тремя несвязанными блоками UI — декомпозировать. Логика запросов — в хуках, не в JSX.
4. **Состояние сервера ≠ состояние UI.** Ответы API кэшируются через слой `api/`; локальный state компонента — только UI-состояния (открыт/закрыт, выбранная вкладка).
5. **Роли — не защита, а отображение.** Скрыть кнопку подписания у сотрудника обязательно, но фронт исходит из того, что настоящую проверку делает бэкенд (403 обрабатываем понятным сообщением).
6. **Статусы — строго enum бэкенда.** Подписи и цвета статусов — в одном словаре; неизвестный статус не должен ронять экран (fallback-подпись + сам статус текстом).
7. **Динамические блоки — по данным, а не по таймерам.** Блок мультибанка появляется только при статусе ANOMALY_DETECTED в ответе API.
8. **Производительность демо:** без тяжёлых UI-библиотек ради одного графика; график прогноза кассы — лёгкий SVG/Canvas. Цель — мгновенный отклик на машине жюри.
9. **TypeScript strict.** `any` запрещён, кроме обоснованных мест с комментарием. `npm run build` без ошибок и предупреждений типов.
