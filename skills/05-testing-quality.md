# Тестирование и качество

## Что покрываем обязательно (юнит-тесты, домен)

1. **RiskScore:** контрольные профили BRD дают точные баллы: кофейня — 815, Ростерс — 610, ТехноСтрой после мультибанка — 760, Ковалев — 495. Сумма вкладов факторов = итоговый балл (база 500).
2. **Decision Engine:** границы коридоров 650 / 520 / 450 — тесты на значениях ±1 от порога; стоп-факторы дают REJECTED без расчёта лимита; FCF ≤ 0 → REJECTED.
3. **State Machine:** каждый разрешённый переход из таблицы BRD — позитивный тест; минимум 5 запрещённых переходов — 409; ceo-approve не-CEO — 403.
4. **Валидатор аномалий:** расхождение выручки > 50% → ANOMALY_DETECTED; после мультибанка флаг снят, лимит +25%.
5. **Intent-парсер:** контрольный набор ≥ 20 запросов, точность ≥ 90%; INFO_ONLY → режим тишины.
6. **Детерминизм:** повторный расчёт/поиск по тому же ИНН даёт идентичный результат (тест на повторяемость, включая офлайн-фолбэк).

## Контрактные тесты API

- Все 11 эндпоинтов: позитивный сценарий + главные негативные (невалидный ИНН, чужая роль, невалидный переход).
- Ответы сверяются с `openapi.yaml` — расхождение контракта и кода = баг контракта или кода, чинится в том же PR.

## Ворота качества перед PR (все пункты — да)

- [ ] Тесты зелёные (юнит + контрактные по своей зоне).
- [ ] Линтер и проверка типов без ошибок (ruff/mypy или pyright; eslint/tsc).
- [ ] `docker compose up --build` с нуля поднимает проект; повторный запуск без дублей сидов.
- [ ] Сквозной сценарий своей зоны проходит вручную по шагам из ТЗ.
- [ ] CHANGELOG обновлён; PR описан по шаблону (см. skills/04-git-changelog.md).
- [ ] Нет мёртвого кода, закомментированных блоков, отладочных принтов и секретов в диффе.

## Ревью чужого PR — чек-лист

1. Соответствует ли изменение ТЗ/BRD (раздел указан в PR)?
2. SOLID: нет ли god-класса, жёстких зависимостей от конкретики в домене, растущих if-цепочек вместо реестра стратегий?
3. Не посчитал ли фронт то, что должен считать бэкенд (и наоборот)?
4. Тесты проверяют поведение, а не реализацию? Есть ли тест на граничные значения порогов?
5. История чистая: коммиты по Conventional Commits, одно изменение — один коммит?

Нашёл нарушение — комментируем с указанием правила из AGENTS.md/скилов и предлагаем, как исправить. Ревью — про код, не про автора.
