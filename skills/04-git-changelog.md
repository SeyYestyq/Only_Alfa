# Git и фиксация изменений

Главный принцип: **по истории репозитория должно быть видно, кто, что, зачем и когда изменил — без вопросов в чат.**

## Ветки

- `main` — всегда собирается и работает (`docker compose up --build`). Прямые коммиты/пуши в main запрещены.
- Одна задача — одна ветка из ТЗ-00: `feature/frontend-spa`, `feature/backend-core`, `feature/scoring-data`, `feature/smart-search`, `feature/qa-acceptance`. Подзадача внутри — `feature/<ветка>-<короткое-имя>`.
- Мёрдж — ежедневно, через Pull Request, минимум один просмотр от другого участника.

## Коммиты — Conventional Commits

Формат: `тип: что сделано и зачем` (до ~72 символов в заголовке).

- `feat:` — новая функциональность: `feat: коридор COUNTER_OFFER в Decision Engine`
- `fix:` — исправление: `fix: идемпотентность сидов демо-профилей`
- `refactor:` — без изменения поведения: `refactor: выделение RiskScore из сервиса заявок (SRP)`
- `test:`, `docs:`, `chore:` — по назначению.

Правила:
- Один коммит = одно логическое изменение. Смешал фичу и рефакторинг — раздели на два коммита.
- Запрещены: `wip`, `fix`, `update`, `asdf`, коммиты «всё сразу» на 40 файлов без причины.
- Сломанный код в ветку своей задачи — можно локально, в PR и main — нельзя: перед пушем тесты и сборка зелёные.

## Pull Request

Описание PR — по шаблону, без исключений:

```
Что сделано: …
Зачем / какой пункт ТЗ или BRD закрывает: … (ссылка на раздел)
Как проверено: … (команды, тесты, ручной сценарий)
Риски / что не доделано: …
```

## CHANGELOG.md

- Формат Keep a Changelog, секции: Added / Changed / Fixed / Removed.
- Каждая строка — из PR, в том же PR, секция `## [Unreleased]`.
- Перед стоп-кодом секция превращается в релиз `## [1.0.0] — 2026-10-26`, ставится тег `v1.0-submit`.

## Отчёт агента в конце задачи (обязателен)

1. Список изменённых файлов и суть каждого изменения.
2. Ссылки на коммиты/PR.
3. Чем проверено: тесты, сценарии, замеры.
4. Что осталось незакоммиченным — должно быть: ничего.

## Запрещено

- Секреты, токены, `.env` в коммитах.
- `git push --force` в общие ветки; переписывание чужой истории.
- Удаление или правка записей аудита `application_events` — в коде и в истории гита аналогично: историю не переписываем задним числом.
