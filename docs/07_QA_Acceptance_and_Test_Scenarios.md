## 2. Пошаговый регламент 3-минутного экспресс-прогона для жюри

Для экспертов, оценивающих решение в условиях ограниченного тайминга, разработан 3-минутный сценарий, охватывающий все ключевые механики конвейера:

```mermaid
gantt
    title Регламент 3-минутного экспресс-прогона для жюри
    dateFormat X
    axisFormat Минута %s
    section Минута 1
    Запуск Docker и проверка /health          : 0, 30
    Экран 1: ДНК бизнеса и касса ИП Смирнова  : 30, 60
    section Минута 2
    Счет кофемашины: Drag-and-Drop PDF        : 60, 90
    Офферы ООО Ростерс и Мультибанк ТехноСтроя: 90, 120
    section Минута 3
    Экран 3: Рентген инспектора (X-Ray)       : 120, 150
    Подписание ПЭП Генеральным директором     : 150, 180
```

### Минута 1: Старт стенда и обзор бизнеса
1. В терминале выполните 1 команду:
   ```bash
   # Вариант А (нативно без Docker, macOS/Linux):
   ./start.sh
   # Вариант Б (Windows):
   start.bat
   # Вариант В (в Docker Compose):
   docker compose up --build -d
   curl http://localhost:8000/health
   ```
2. Откройте в браузере `http://localhost:5173` (или `http://localhost:8080` в Docker). При запуске через `./start.sh` браузер откроется автоматически!
3. В верхней панели **Demo Control Bar** выбрана компания **«ИП Смирнов А.В.»**.
4. Ознакомьтесь с Экраном 1: 360°-ДНК бизнеса, 60-дневный график кассы, радар рисков и умный поиск.

### Минута 2: Бизнес-поиск, цифровой след и встречные предложения
1. Перейдите во вкладку **«Поиск»** (Search-to-Credit) $\rightarrow$ нажмите чипс *«Ростер для кофе Giesen W15A 2.5 млн»*. Система мгновенно находит оборудование, поставщиков и сохраняет цифровой след.
2. Перейдите во вкладку **«Счета к оплате»** $\rightarrow$ нажмите **«Загрузить демо-счет»** (счет на кофемашину La Marzocco от ООО «КофеТехПро» на 900 000 ₽). Система за 40 мс разбирает текстовый слой PDF, верифицирует ИНН поставщика и открывает предзаполненную заявку на недостающую сумму.
3. В переключателе компаний выберите **«ООО Ростерс Кафе»** (Score 610) $\rightarrow$ перейдите на Экран заявки и убедитесь в генерации **4 встречных офферов** (срок, залог, овердрафт).

### Минута 3: Мультибанк, Цифровой след инспектора, Рентген (X-Ray) и ПЭП
1. Переключитесь на **«ООО ТехноСтрой»** (Score 295, аномалия) $\rightarrow$ нажмите **«Подтянуть Мультибанк»** $\rightarrow$ балл вырастает до **760**, лимит до 2,5 млн ₽.
2. В Control Bar переключите режим на **«Глазами банка (Инспектор)»**:
   - На экране **«Клиенты банка»** изучите блок **«Search-to-Offer AI · Цифровой след»** (показывает запрос клиента по ростеру, поставщика и кнопку *«Предложить финансирование в чат»* в 1 клик).
   - На экране **«Портфель»** изучите карточку агрегированных поисковых интентов клиентов.
   - Изучите Экран 3 (**Bank X-Ray**): P&L сделки, Waterfall скоринга, карту OSM и протокол аудита.
3. Вернитесь в режим клиента под ролью `CEO_OWNER` и нажмите **«Подписать договор ПЭП»**. Заявка переходит в статус `FUNDED`, кредитные средства зачислены на баланс!

## 3. Сценарии сквозного тестирования 5 контрастных профилей

### Сценарий 1: ИП Смирнов (Зеленый коридор, 815 баллов, Fast Track)
- **Суть кейса:** Высоконадежный предприниматель с чистой историей в БКИ и стабильной выручкой 1,4 млн ₽/мес.
- **Ожидаемый результат:**
  * RiskScore: **815 баллов**.
  * Статус: `APPROVED`.
  * Ставка: **14.5%** (Ключевая ставка $14.0\% + \text{спред } 1.5\% - \text{дисконт за риск } 1.0\%$).
  * Подписание: в 1 лицо ролью `IP_OWNER`.

### Сценарий 2: ООО «Ростерс Кафе» (Желтый коридор, 610 баллов, 4 оффера, Maker-Checker)
- **Суть кейса:** Растущая сеть кофеен с высокой кредитной нагрузкой. Платёж по запросу 3 млн ₽ превышает свободный денежный поток FCF.
- **Ожидаемый результат:**
  * RiskScore: **610 баллов**.
  * Статус: `COUNTER_OFFER`.
  * Конвейер формирует 4 альтернативных варианта. Бухгалтер выбирает оффер с обеспечением под залог кофемашин $\rightarrow$ заявка переходит в статус `AWAITING_CEO_APPROVAL`. Директор акцептует ключом ПЭП.

### Сценарий 3: ООО «ТехноСтрой» (Аномалия 295 $\rightarrow$ Мультибанк $\rightarrow$ 760 баллов)
- **Суть кейса:** Заявлена выручка 2,4 млн ₽, но по счетам в Альфа-Банке проходит только 600 тыс. ₽.
- **Ожидаемый результат:**
  * Первичный статус: `ANOMALY_VERIFICATION` (балл 295).
  * Действие: Вызов `POST /api/v1/applications/{id}/verify-multibank`.
  * Повторный скоринг: Добавление фактора `CF_MULTIBANK_VERIFIED` (+90 баллов), пересчет балла до **760**, лимит увеличен на **+25%**.

### Сценарий 4: ИП Ковалев (Оранжевый коридор, 495 баллов, Стол инспектора)
- **Суть кейса:** Молодой бизнес (9 месяцев) с пограничным баллом скоринга.
- **Ожидаемый результат:**
  * Статус: `MANUAL_REVIEW`.
  * Инспектор видит заявку на Столе разбора (Bank X-Ray) $\rightarrow$ нажимает кнопку дозапроса контракта поставщика (`NEED_MORE_INFO`). Клиент подгружает файл $\rightarrow$ инспектор одобряет сделку.

### Сценарий 5: ООО «Бодрость Плюс» (Красный коридор, 0 баллов, Hard Stop, Чек-лист)
- **Суть кейса:** Организация с исками ФССП на сумму 1,8 млн ₽ и признаками предбанкротного состояния.
- **Ожидаемый результат:**
  * Срабатывание Hard Stop: RiskScore = **0 баллов**.
  * Статус: `REJECTED`.
  * Клиент видит не просто отказ, а **понятный чек-лист оздоровления**:
    1. Погасить задолженность по исполнительным листам ФССП на сумму 1 800 000 ₽.
    2. Предоставить положительную промежуточную отчетность ГИР БО.
    3. Повторная подача доступна через 30 календарных дней.

## 4. Автоматизированное тестирование (Pytest & TypeScript)

В репозитории реализован полный набор юнит- и интеграционных тестов:

```bash
# 1. Запуск 56 тестов бэкенда (pytest)
cd backend
../.venv/bin/python -m pytest -v

# Ожидаемый результат: 56 passed in ~0.9s
```

### Структура тестового покрытия бэкенда:
- `tests/test_scoring.py`: верификация баллов 5 профилей (815, 610, 760, 495, 0).
- `tests/test_decision_engine.py`: формулы ставок от ставки ЦБ, расчет аннуитета и лимита FCF.
- `tests/test_fsm.py`: валидация 21 перехода, проверка кодов 403 (роли) и 409 (недопустимый переход).
- `tests/test_multibank.py`: снятие аномалии выручки, дельта скоринга `score_delta = 465`.
- `tests/test_pdf_parser.py`: парсинг 3 шаблонов и реальных PDF-счетов через pdfplumber.
- `tests/test_intent_parser.py`: точность 100% на контрольном датасете запросов умного поиска.

```bash
# 2. Проверка строгой типизации TypeScript и сборка SPA
cd frontend
npm run typecheck
npm run build

# Ожидаемый результат: 0 ошибок типизации, успешная компиляция бандла
```

## 5. Тестирование API через cURL и Postman

Для проверки API без использования графического интерфейса подготовлены готовая коллекция **`Postman_Collection.json`** и примеры прямых запросов:

### Проверка работоспособности стенда:
```bash
curl -X GET http://localhost:8000/health
```

### Заведение кредитной заявки:
```bash
curl -X POST http://localhost:8000/api/v1/applications \
  -H "Content-Type: application/json" \
  -d '{
    "company_id": "c1a2b3c4-0001-4000-8000-000000000001",
    "product_type": "INVEST_LEASING",
    "requested_amount_rub": 900000,
    "term_months": 24,
    "declared_monthly_revenue": 1400000,
    "initiator_role": "IP_OWNER"
  }'
```

### Подтверждение Мультибанка:
```bash
curl -X POST http://localhost:8000/api/v1/applications/{application_id}/verify-multibank
```

### Подписание договора ПЭП Генеральным директором:
```bash
curl -X POST http://localhost:8000/api/v1/applications/{application_id}/ceo-approve \
  -H "Content-Type: application/json" \
  -d '{
    "actor_role": "CEO_OWNER",
    "confirmation_code": "1234"
  }'
```
