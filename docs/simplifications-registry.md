# Реестр упрощений и замоканных интеграций

Документ фиксирует, что в демо-контуре заменено симулятором или упрощено, почему это допустимо для Чекпоинта-1 и чем риск закрыт. Главный принцип: упрощается внешняя интеграция, но не кредитное ядро.

## 1. Правила реестра

Статусы:

- **Симулятор** — внешний источник заменён детерминированной функцией; интернет не требуется.
- **Опционально** — компонент выключен по умолчанию и не влияет на критический путь.
- **Фолбэк** — основной путь может быть заменён локальным режимом без потери бизнес-решения.
- **Ограничение** — функция упрощена, но её отсутствие явно возвращает ошибку, а не поддельный результат.

Допустимость упрощения определяется тремя условиями:

1. упрощение не меняет контракт API и модель решения;
2. поведение детерминировано и воспроизводимо на демо;
3. ограничение явно видно в ответе, проверке или документации.

## 3. Детали по интеграциям

### 3.1. ЕГРЮЛ и проверка ИНН

`backend/app/infra/registry_simulator.py`:

- `validate_inn` поддерживает 10 и 12 цифр и проверяет контрольные суммы по алгоритму ФНС;
- `simulate_company` берёт `sha256(inn)`, инициализирует `random.Random` и собирает профиль: ОКВЭД-кластер, город, выручку, рост, закупки, аренду, налоги, платёж БКИ, возраст, GeoScore, BuyerScore;
- юридическая форма определяется длиной ИНН: 10 цифр — ООО, 12 — ИП;
- один и тот же ИНН всегда даёт один и тот же профиль, пока запись не сохранена в БД.

Особенность демо: `lookup-inn` сначала ищет ИНН в БД. Четыре из пяти демо-ИНН синтетические и не проходят контрольную сумму, но возвращаются как засеянные профили. Для нового ИНН контрольная сумма обязательна.

Демо получает 360°-портрет по любому валидному ИНН без внешней сети. Реальный статус компании, история руководителей, достоверные ОКВЭД и выручка не проверяются.

### 3.2. БКИ

БКИ не вызывается как сервис. В профиле компании уже есть:

- `bki_overdue_days` — текущая просрочка;
- `bki_history_months` — длина истории;
- `bki_active_contracts` — число договоров;
- `bki_monthly_payment` — платёж по кредитам.

Правила `domain/scoring/rules.py` переводят эти поля в дискретный фактор:

| Условие | Код | Балл |
|---|---|---:|
| Просрочка > 30 дней | `BKI_STOP_OVERDUE` | −180 |
| Просрочка 5–25 дней | `BKI_TECH_OVERDUE` | −85 |
| История 0 месяцев | `BKI_NO_HISTORY` | 0 |
| 0 просрочек и история ≥ 24 месяцев | `BKI_CLEAN_HIGH` | +130 |
| Иначе | `BKI_CLEAN_STD` | +80 |

Контрольные значения: Смирнов 130, Ростерс 130, Ковалев −85, Бодрость Плюс −180.

### 3.3. ФССП

В скоринге ФССП — Hard Stop, если сумма исполнительных производств больше 20% месячного оборота. В демо это «Бодрость Плюс»: 320 000 ₽ при обороте 400 000 ₽, порог 80 000 ₽. Поэтому заявка отклоняется независимо от остальных факторов.

В антифроде поставщика `run_antifraud` проверяет контрольную сумму ИНН и симулированный профиль: `is_egrul_active` и `fssp_amount == 0`. Для реального пилота требуется подключение ФССП и ЕГРЮЛ; текущая проверка не заменяет юридическую проверку контрагента.

### 3.4. Open Banking и Мультибанк

Сценарий:

1. Заявка «ТехноСтрой» приходит с заявленной выручкой 6 000 000 ₽/мес., а в Альфа-Банке — 1 800 000 ₽/мес.
2. Отклонение 233% > 50%, статус `ANOMALY_VERIFICATION`.
3. `POST /applications/{id}/verify-multibank` добавляет 4 200 000 ₽ внешней выручки, ставит `is_multibank_verified = true`.
4. Фактор меняется с `CF_CRITICAL_DROP` (−200) на `CF_MULTIBANK_VERIFIED` (+90), DSCR пересчитывается, балл становится 760.
5. Лимит умножается на 1,25, ставка 15,5%, заявка одобрена.
6. Повторная заявка использует подтверждённый оборот 1,8 + 4,2 = 6,0 млн ₽, поэтому аномалия не возвращается: статус APPROVED, балл 760.

Для остальных компаний симулятор добавляет 35% от оборота в Альфе. Это демонстрационная эвристика, а не реальная выписка.

### 3.5. OpenAI-compatible адаптер

`backend/app/infra/openai_adapter.py`:

- режим включается только при `AI_PROVIDER_MODE=OPENAI_COMPATIBLE`;
- нужны `OPENAI_BASE_URL` и `OPENAI_MODEL_NAME`; ключ опционален, если шлюз не требует авторизации;
- таймаут — `OPENAI_TIMEOUT_MS`, по умолчанию 1500 мс;
- при любой ошибке, пустом ответе или таймауте возвращается `None`;
- текст ИИ не влияет на `credit_badge`, балл, ставку и статус заявки.

Следовательно, отключение ИИ не меняет кредитное решение. Это соответствует требованию «никаких платных API и LLM в критическом пути».

### 3.6. PDF без OCR

`backend/app/infra/invoice_parser.py`:

- проверяет сигнатуру `%PDF`;
- извлекает текст через `pdfplumber`;
- ищет ИНН (10/12 цифр), итог, НДС, поставщика и назначение;
- при отсутствии ИНН или суммы выбрасывает `InvoiceParseError` → 422;
- поддерживает 3 демо-шаблона: `LA_MARZOCCO`, `ROSTERS_EQUIP`, `CABLE_VVG`.

Ограничение: сканы и фотографии без текстового слоя не поддерживаются. Для продуктивного контура нужен OCR и контроль качества извлечения, но в демо текстовый PDF обрабатывается за миллисекунды и не требует внешнего сервиса.

### 3.7. SQLite как локальный фолбэк

В Docker `DATABASE_URL` указывает на PostgreSQL. Если переменная не задана, `Settings` использует `sqlite:///./alfa.db`. Это удобно для локального запуска и тестов, но не является продуктивной конфигурацией:

- нет конкурентной записи на уровне PostgreSQL;
- JSONB заменяется на JSON;
- миграции не ведутся, схема создаётся `create_all`.

Для демо и автотестов этого достаточно; для пилота нужны PostgreSQL, Alembic и резервное копирование.

### 3.8. OSM iframe

`XrayService` формирует `map_url` с `bbox` и маркером. Карта не требует API-ключа и не входит в расчёт. Если openstreetmap.org недоступен, экран 3 теряет только визуальный слой; GeoScore и координаты остаются в ответе.

## 4. Что не упрощено

| Компонент | Почему не упрощён | Где проверяется |
|---|---|---|
| **Дискретный RiskScore** | Балл — основа решения; «примерные» диапазоны недопустимы. База 500 и пять факторов с фиксированными баллами | `test_scoring.py`, контрольные 815 / 610 / 760 / 495 / 0 |
| **Decision Engine** | Коридоры 650 / 520 / 450, FCF, `MaxPayment`, ставка и лимит считаются по формулам; лимит выводится из аннуитета через `calculate_max_principal` | `test_smirnov_815_approved_rate_14_5`, `test_rosters_610_counter_offer_four_variants_rate_18`, `test_tekhnostroy_760_after_multibank_rate_15_5` |
| **State Machine** | Переходы и роли — юридически значимая логика; обход запрещён | `test_signature_for_ip_and_ooo`, `test_manual_review_flow_need_more_info`, `test_rejected_application_cannot_be_signed` |
| **ПЭП: права и статус** | Подписывает только владелец: `CEO_OWNER` для ООО, `IP_OWNER` для ИП; неверная роль — 403, неверный статус — 409 | те же тесты; отдельный разбор — в [state-machine-ip-vs-ooo.md](./state-machine-ip-vs-ooo.md) |
| **Аудит** | Каждое действие пишет `application_events`; проверки — `application_checks`; Xray читает журнал | `test_xray_contains_pnl_waterfall_and_events` |
| **Проверка ИНН** | Контрольная сумма — минимальный барьер от мусорных данных | `test_negative_codes_422_403_409`, `test_lookup_inn_is_deterministic` |
| **Прогноз кассы** | 60 дней, аренда/ФОТ и налоги отдельными событиями, разрыв показывается до выдачи | `test_kovalev_495_manual_review_and_cash_gap_140k`, `test_dashboard_structure` |
| **Идемпотентность сидера** | Повторный старт не должен плодить демо-данные | `test_seed_is_idempotent` |

Отдельно: **криптографическая подпись ПЭП не реализована**. Проверяются роль, статус и факт подписания, пишется событие `PES_SIGNED`. Это демонстрационная логическая подпись; для продукта нужны КриптоПро/ГОСТ, ключи и юридически значимый документооборот.

## 5. Путь к продуктиву

| Что заменить | Приоритет | Минимальное требование |
|---|---|---|
| ЕГРЮЛ, БКИ, ФССП, Open Banking | Высокий | Реальные API с SLA, кэш, обработка недоступности, версионирование ответов |
| Аутентификация и роли | Высокий | SSO/Keycloak, подписанные токены, проверка роли на сервере, а не в теле запроса |
| ПЭП | Высокий | Криптопровайдер, сертификаты, журнал подписей, юридическая экспертиза |
| PDF/OCR | Средний | OCR для сканов, валидация полей, очередь обработки, лимиты |
| PostgreSQL и миграции | Средний | Alembic, резервное копирование, реплика, мониторинг |
| Наблюдаемость | Средний | Метрики latency/error rate, трассировка, алерты по Tier-0 |
| ИИ-обогащение | Низкий | Отдельный шлюз, маскирование данных, бюджет токенов, оценка качества |

## 6. Как проверить

```bash
# Все тесты, включая симуляторы, PDF и коды ошибок
cd backend && ../.venv/bin/python -m pytest -q

# Детерминированность lookup-inn
curl -s -X POST http://localhost:8000/api/v1/companies/lookup-inn \
  -H 'Content-Type: application/json' \
  -d '{"inn":"7734567893"}'

# Мультибанк: 295 → 760
# 1) создать заявку ТехноСтрой, 2) вызвать verify-multibank

# PDF: шаблон и битый файл
curl -s http://localhost:8000/api/v1/applications/invoice-templates
```

Ожидаемо: 46 passed; `lookup-inn` при повторном вызове отдаёт `source: DATABASE` и тот же `id`; `verify-multibank` — `score_delta: 465`; битый PDF — 422.
